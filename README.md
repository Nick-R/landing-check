# Сверка

Проверяет, даёт ли страница то, что обещает реклама, и предлагает готовые правки.

Открыть: https://landing-check-nine.vercel.app

Вставляете ссылку и текст объявления - получаете оценку соответствия и от 3 до 7 правок по важности. У каждой правки: что не так, почему это важно, готовый текст на замену. Правку можно принять или отклонить. Принятые собираются в один список. У каждой проверки своя ссылка.

## Как устроено

```
ввод -> лимиты -> загрузка страницы -> разбор текста -> модель (ответ по схеме) -> проверка схемы -> Postgres -> отчёт
```

- `src/lib/net` - загрузка чужой страницы с защитой от запросов во внутреннюю сеть
- `src/lib/page` - разбор HTML: заголовки, призывы, видимый текст
- `src/lib/llm` - инструкция, схема ответа, вызов модели через OpenAI-совместимый API
- `src/lib/limits.ts` - лимит проверок на адрес и дневной потолок расходов
- `src/lib/checks.ts`, `src/lib/decisions.ts` - хранение и логика "принять / отклонить"
- `migrations/` - схема базы, применяется при сборке

Стек: Next.js (App Router), TypeScript в строгом режиме, Postgres, zod.

## Защита

Сервис открыт всем, поэтому:

- Ссылки только http и https, стандартные порты. Внутренние адреса запрещены дважды: по виду ссылки и по IP в момент соединения (от подмены DNS). Каждое перенаправление проверяется заново.
- Ответ страницы ограничен по размеру (1,5 МБ) и времени (10 с).
- Лимит проверок с одного адреса в час и в сутки. Адрес хранится только как хеш.
- Дневной потолок расходов на модель: деньги бронируются до вызова, после потолка проверки отключаются до завтра.
- Текст страницы для модели - данные, а не указания: он стоит между метками, системная инструкция запрещает его выполнять. Скрытые блоки страницы в модель не попадают.
- Ответ модели проверяется по схеме на сервере. Цитаты "сейчас на странице" сверяются с текстом страницы: неподтверждённая цитата помечается.
- Ключи только в переменных окружения.

## Запуск

```
cp .env.example .env.local   # заполнить
npm install
npm run migrate
npm run dev
```

## Проверки

```
npm run check                                        # типы, линтер, модульные тесты
DATABASE_URL_TEST=postgres://... npm test            # плюс тесты с базой
DATABASE_URL_TEST=postgres://... npm run test:e2e    # сквозной тест в браузере
```

Сквозной тест идёт без сети и без модели: страница-образец с диска, ответ-заглушка (`LLM_MOCK=1`).

## Ограничения

- Страницы, которые целиком собираются скриптами в браузере, сервис не читает и сразу об этом говорит.
- Оценивается только текст: дизайн, скорость и вёрстка вне проверки.
